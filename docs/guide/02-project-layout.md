# Project layout

Everything entlite touches lives in one `ent/` directory. You write two of the
folders, the generator owns the rest.

<!-- tree:start -->
```
ent/
├── schema/            # you write: one file per entity
├── logic/             # you write: Go funcs for DefaultFunc and Validate
├── contract/          # the input for sqlc and buf
│   ├── proto/         # generated: schema.proto, plus your custom .proto
│   └── sqlc/          # generated: schema.sql, queries.sql, plus your custom .sql
├── gen/               # the output, rewritten on every run
│   ├── db/            # generated: typed wrapper, pointers instead of null types
│   │   └── internal/  # generated: raw sqlc output, never import it
│   ├── pb/            # generated: proto messages and the connect service
│   └── ts/            # generated: TypeScript client
├── buf.yaml
├── buf.gen.yaml
├── buf.lock
├── sqlc.yaml          # dialect and sqlc settings
└── generate.go        # the go:generate lines that run the pipeline
```
<!-- tree:end -->

## Yours

| Folder | Holds |
| --- | --- |
| `schema/` | one file per entity, the single source of truth |
| `logic/` | plain Go funcs the schema points at, e.g. `logic.NewUUID` |
| `contract/sqlc/custom.sql` | queries the dsl cannot express |
| `contract/proto/custom.proto` | messages and services you write by hand |

## Generated

Everything under `gen/` is rewritten on every run. Files there start with a
`Code generated by entlite. DO NOT EDIT.` line. The same is true for
`schema.sql`, `queries.sql` and `schema.proto` in `contract/`.

Your custom files in `contract/` are never touched. They sit next to the
generated ones and sqlc and buf read both.

## Why contract and gen are separate

`contract/` is the input for the outside tools, `gen/` is their output. Keeping
them apart means you can read the sql and the proto that entlite produced, and
commit them, without digging through generated Go.
